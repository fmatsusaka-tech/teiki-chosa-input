# Googleスプレッドシート登録APIの設定

登録先: `定期調査データバンク` / `調査原票`

## 1. Apps Scriptを作る

1. 登録先スプレッドシートを開く。
2. `拡張機能` → `Apps Script`。
3. 初期コードを削除し、このフォルダの `Code.gs` を貼り付ける。
4. 保存する。

## 2. APIトークンを設定する

1. Apps Scriptの左側で `プロジェクトの設定` を開く。
2. `スクリプト プロパティ` に次を追加する。
   - プロパティ: `API_TOKEN`
   - 値: 推測されにくい長い文字列

## 3. Webアプリとしてデプロイする

1. `デプロイ` → `新しいデプロイ`。
2. 種類は `ウェブアプリ`。
3. 実行するユーザーは `自分`。
4. アクセスできるユーザーは `全員`。
5. デプロイ後に表示される `/exec` で終わるURLを控える。

## 4. 入力アプリとの関係

オンライン試用版の入力アプリは、ブラウザからこのWebアプリを直接呼び出しません。
Google認証情報を保持するNext.jsサーバーを経由して調査原票へ保存します。このWebアプリは
既存連携や保守用として残し、URLやAPIトークンを`NEXT_PUBLIC_*`環境変数へ設定しないでください。

## 登録仕様

- 同じ登録IDは再登録しない。
- 複数レコードを一度に追記する。
- 必須項目: 計測日、園地、品種。
- 横径、糖度、酸度の欠測は空欄で保存し、0へ変換しない。
- 登録時刻はGAS側で付与する。
- 送信元の原文メモも保存する。

## Input正本27列への移行

Apps Scriptエディタから`setupCanonicalRawSheet`を1回実行してください。不足している管理列を
既存列の末尾へ追加し、既存行の更新日時・改訂番号・データ状態を補完します。既存列の移動、
改名、削除は行いません。

新規登録では編集キーを生成し、`調査原票`にはSHA-256ハッシュだけを保存します。平文キーは
登録応答の`editCredentials`で一度だけ返し、Spreadsheetやログへ保存しません。正式な列仕様は
[`docs/input-data-dictionary.md`](../docs/input-data-dictionary.md)を参照してください。

## 調査データの再生成

Apps Scriptエディタから `regenerateSurveyData` を実行すると、`調査原票` の全行を
`調査データ` へ再生成できます。初回実行時はGoogle Sheetsへのアクセス許可が必要です。

`setupSurveyActiveStatusColumn`を実行すると、`調査データ`の末尾へ`有効状態`を追加し、
`有効`・`無効`だけを選べる入力規則を設定します。既存行は推測更新せず空欄のままです。
再生成時は、同じ登録IDに設定済みの有効状態を保持します。

- `横径1`〜`横径10` は `玉1横径`〜`玉10横径` へ同じ順序でコピーします。
- 未測定の横径は空欄のまま保存し、横径の個数・平均・最小・最大の計算から除外します。
- `備考` の直後（既存の `横径個数` より前）に玉ごとの列を追加します。
- 糖度、酸度、糖酸比、データ状態、入力方法、入力者、送信元などの既存列は、見出し名で
  対応付けるため列順を変更してもずれません。予測処理向けの `横径平均` も従来どおり生成します。
- 年度（4月始まり）、年、月、調査基準月、調査区分、糖酸比、データ状態も原票から再計算します。
  25日以降は翌月の前半、1〜10日は当月の前半、11〜20日は当月の中頃として扱い、
  21〜24日の調査区分は未定義のため空欄にします。
- 糖度または酸度が欠測の場合と酸度が0の場合、糖酸比は空欄にします。調査日、園地、品種が
  すべて有効ならデータ状態は `有効`、それ以外は `要確認` とします。

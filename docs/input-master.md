# 入力マスタと補正学習データ

## 入力マスタ

開発用データバンクの `入力マスタ` タブを、文章解析で使用する正式マスタとします。
アプリの再公開は不要で、次回の画面読み込みから編集内容が反映されます。

| 見出し | 内容 |
| --- | --- |
| 種別 | `園地`、`品種`、`処理区` のいずれか |
| 正式名称 | 確認画面と調査原票へ使用する名称 |
| 別名 | メモに現れる別表記。複数の場合は読点・カンマ・セミコロンで区切る |
| 既定品種 | 種別が園地の場合に自動設定する品種。分からない場合は空欄 |
| 有効 | チェック済みの行だけ解析に使用 |

### 早生品種の正式名称

次の入力名は、すべて正式品種名 `早生（宮川・興津 等、又は山下紅）` として扱います。

- 宮川
- 興津
- 山下紅
- 早生

`入力マスタ`では、正式名称を上記の正式品種名、別名を
`宮川、興津、山下紅、早生`として登録してください。園地の既定品種にも短縮名ではなく
正式品種名を使用します。

### 品種候補の表示順

品種候補は次の正式名称・順番で表示します。

1. 早生（宮川・興津 等、又は山下紅）
2. 田口
3. 極早生
4. ゆら早生
5. YN26
6. 向山
7. 晩生（林など）
8. 丹生
9. 清見
10. せとか
11. ポンカン
12. 不知火

`興津早生`は早生へ、`田口早生`は田口へ、`林`は晩生（林など）へ正規化します。

マスタを取得できない場合は、アプリ内の組み込みマスタへ自動的に切り替わります。
未登録の園地名でも、後ろに数値のまとまりがあれば警告付き候補として解析し、
利用者が園地名・品種などを補正できます。

確認・補正画面の品種欄には、有効な品種マスタをプルダウン候補として表示します。
新品種やマスタ外の品種は、プルダウンの「自由入力」を選択して入力できます。
解析結果がマスタ外の場合は自由入力値として保持し、利用者がそのまま補正できます。
マスタとの不一致を理由に解析や登録操作を停止しません。

## 未登録の園地名・処理区名の自動学習

Apps Scriptの`syncInputMasterFromRawSheet`が、`調査原票`に登録された園地名・処理区の
うち`入力マスタ`に無い値を検知し、`有効`をチェック済みの状態で自動追加します。
承認フローは設けず、誤って追加された値は運用担当者が`入力マスタ`の該当行の
`有効`チェックを外すことで解析候補から除外します。

`createInputMasterSyncTrigger`をApps Scriptエディタから一度だけ実行すると、
30分ごとに`syncInputMasterFromRawSheet`を自動実行する時間主導トリガーが設定されます。

### 園地と品種の紐づけ（既定品種1〜3）

`入力マスタ`の`既定品種`列（既定品種1）に加え、`既定品種2`・`既定品種3`列を使い、
1つの園地につき最大3品種まで紐づけて記録します。対象は`品種`マスタに登録済みの
正式名称・別名に一致する値だけで、未知の品種名を新規に追加することはありません
（品種名自体の学習・正規化は別Issueの範囲）。

- 各園地の既定品種スロットは、`調査原票`での観測順（先着）で空欄のスロットだけを埋めます。
- 既に値が入っているスロット（手動登録・過去の自動補充のいずれも）は上書きしません。
- 4品種目以降が観測されても追加しません。別の品種へ差し替えたい場合は、
  `入力マスタ`のセルを手動で編集してください。
- 確認・補正画面での品種プルダウンを既定品種1〜3だけに絞る変更は、この機能の
  対象外です（将来のIssueで検討します）。

## 解析補正ログ

文章入力を確認・補正して調査原票へ保存したとき、学習材料として
`解析補正ログ` タブへ次の組み合わせを記録します。

- 原文メモ
- 補正後の園地名・品種・処理区・備考
- 補正後の横径・糖度・酸度
- 入力方法

補正ログへの記録に失敗しても、正本である `調査原票` の保存は取り消しません。
将来の夜間学習処理はこのログを入力とし、正本を書き換えないものとします。
